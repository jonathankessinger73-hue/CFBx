# CFBx backend

Play-money exchange for college football programs. Prices move on real
results versus real Vegas spreads. This repo turns the single-file
prototype (`reference/cfbx-artifact.html`) into a server-backed product.
The full product spec is `CFBx-handoff-spec.md`.

The server is the only authority on **price**, **cash** and **holdings**.
Clients ask questions or request trades, and they never send a price.

## Layout

```
reference/cfbx-artifact.html   the prototype, source of the seed tables
data/*.json                    generated by `npm run extract` from the artifact; don't hand-edit
db/migrations/                 schema, RLS, and the atomic SQL write functions
src/engine/pricing.js          price formulas ported from the artifact (pure functions)
src/engine/replay.js           applies completed games to a market
src/seed/                      builds and writes the initial database contents
src/api/                       Express API (app.js), Supabase token auth (auth.js)
src/db/                        pg setup and queries
src/cfbd/                      CollegeFootballData client and team-name matching
src/jobs/                      daily sync (syncSeason.js) and its CLI (daily.js)
.github/workflows/             CI and the scheduled CFBD sync
```

## Setup

1. Create a Supabase project. Copy `.env.example` to `.env` and fill it in.
   `DATABASE_URL` is the Postgres connection string from Project Settings → Database.
2. `npm install`
3. `npm run migrate`. This applies `db/migrations/*.sql` in order. You can also paste
   the files into the Supabase SQL editor.
4. `npm run seed` loads the 138 teams at IPO prices and replays the completed 2026
   games to build price history. It also loads the rest of the schedule.
   The script refuses to run if teams already exist.
5. `npm run dev` starts the API on `:3000`.

For the scheduled job, create GitHub environments `staging` and later
`production`. Give each one the secrets `DATABASE_URL` and `CFBD_API_KEY`. The
workflow uses `staging` until the repo variable `CFBX_JOB_ENVIRONMENT` is set to
`production`. For a manual run with the "dry run" box checked, open
Actions → CFBD sync → Run workflow. Locally, run `npm run job:daily -- --dry-run`.

## API

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/teams` | — | All teams with price, colors, mascot, last-game cover info |
| GET | `/teams/:id` | — | `team`, `price_history` (IPO then after each game), `game_log`, `upcoming` (`line_is_real: false` = projected) |
| GET | `/leaderboard` | — | Rank, display name, net worth. User ids are never exposed. |
| GET | `/me` | ✓ | Cash, holdings value, net worth. Creates the account with $10,000 on first call. |
| GET | `/me/holdings` | ✓ | Holdings valued at current prices |
| GET | `/me/transactions` | ✓ | Newest first. Page with `?before=<id>&limit=`. |
| POST | `/trade` | ✓ | `{team_id, side: "buy"\|"sell", shares: <int>}`. Any other field (like `price`) is ignored. |

Auth: `Authorization: Bearer <Supabase access token>`. Trade errors return
`{error}` with one of these codes: `invalid_team`, `invalid_side`, `invalid_shares`,
`unknown_team` (404), `insufficient_funds`, `insufficient_shares`.

## Tests

```
npm test                                   # engine + seed tests; DB tests skip
TEST_DATABASE_URL=postgres://postgres:postgres@localhost:5432/postgres npm test
```

With `TEST_DATABASE_URL` set, each test file creates a throwaway database and
applies the real migrations. It adds a small stand-in for Supabase's `auth`
schema and roles. CI runs the tests against Postgres 16 this way.

## Decisions and deviations from the spec

- **Database access goes through `pg` + `DATABASE_URL`, not supabase-js.** The API,
  the seed and the job all connect directly to the Supabase Postgres. Supabase JS
  is used only to verify login tokens. This lets the exact production SQL run in
  tests. It also adds one env var that the spec doesn't list.
- **Trades run inside Postgres.** `execute_trade()` does steps 1–4 of the spec's
  pseudocode as one SQL transaction. It locks the user's row, so parallel requests
  can't overdraw an account. Only the service role can call it.
- **`schedule.line` uses CFBD's raw convention** (negative = home favored), as the
  spec says. The artifact stored the opposite sign (expected home margin), so the
  seed negates it. The engine converts with `spreadToExpectedHomeMargin`.
- **Real lines for completed games** are the average of all providers' spreads
  from `/lines`, matched by CFBD game id. If `/lines` has none, the job uses the
  schedule's line. If that is missing too, it uses the SP+ proxy.
- **`transactions` is enforced append-only** by a trigger. It is not only a convention.
- **Game application is idempotent.** `apply_game_result()` skips a game that is
  already completed. It rejects the update if a team's price changed after the
  job read it. The workflow also never runs two syncs at once.
- **Schema additions:** `teams.ipo_price` (for season % change and chart start),
  `schedule.cfbd_game_id`, `price_events.schedule_id` and `summary`, and
  `users.display_name`. RLS is on for every table. The anon key can read only
  market data, and users can read only their own rows.
- `price_events.pct_change` is the realized move. It differs from the formula's
  percentage only when the $3 floor applies.
- The artifact's "week 1" includes the week-0 games, so some teams show
  two week-1 events. This is kept as-is.
- Known gaps from the spec are kept on purpose. Sacramento State ($13.00) and North
  Dakota State ($14.50) have manually floored IPO prices. Prestige ignores
  seasons before 2014.
